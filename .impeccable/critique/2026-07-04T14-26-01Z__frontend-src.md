## Anti-Patterns Verdict

**不再是 slop，但尚未锋利。** Round 2 改动方向正确 —— Dashboard 明显更好，气质更冷静，无障碍底线提升。但修复应用不均：部分落在 Dashboard 上从未传播到 Statistics 或 Settings，且至少一处引入回归（卡片视图删除绕过新 ConfirmDialog）。代码不再像生成样板，但仍像未被真实用户压力测试过的原型。

**Deterministic scan：** `detect.mjs` 报告 0 findings，exit 0。无圆角违规、无硬编码颜色、无硬编码 8px。DESIGN.md 合规。人工抽查确认所有圆角派生自 `var(--radius)` (10px)，品牌锚点色通过 `--ring`/`--pending` token 使用，非装饰性硬编码。

**Visual overlays：** 跳过 —— sub-agent 无浏览器自动化。

## Overall Impression

Dashboard 的情感弧线现在打磨得很好。Subscriptions 和 Settings 页打破了 Dashboard 建立的信任。一个 P0 回归（卡片视图删除无确认）直接违背产品的"可靠"承诺。最大的剩余机会：把 Round 2 的修复均匀传播到所有页面，特别是删除确认和图表诚实性。

## What's Working

1. **Dashboard 重排序是产品级改进。** Due Soon 第一焦点 + "all clear"肯定状态 + 诚实单数字投影，直接服务 PRODUCT.md 原则 1 和 3。Round 2 最强修复。
2. **Acknowledge 反馈闭环完整。** Toast（"好的，已记下，下次将在 X 提醒你"）闭合交互循环 —— 用户知道系统听到了，知道下次提醒何时来。
3. **无障碍底线实质提升。** Skip link、aria-current、aria-live、role="menuitemradio" + aria-checked、prefers-reduced-motion、Graphite 700 (9.0:1 AA)。可验证的改进。

## Priority Issues

### [P0] 卡片视图删除绕过 ConfirmDialog — 静默数据丢失
- **What**：`SubscriptionsPage` 卡片视图传 `onDelete={handleDelete}` 给 `SubscriptionCard`，卡片的 ghost trash 按钮直接调 `onDelete(sub.id)` → `deleteSubscription(id)`。表格视图正确走 `setDeleteTarget` → `ConfirmDialog`，但卡片视图从未接线。
- **Why it matters**：这是 ConfirmDialog 迁移引入的回归。用户切到卡片视图点 trash 图标，零确认零 undo 丢失订阅。直接违反 PRODUCT.md"可靠"承诺，是破坏财务工具信任的 bug。
- **Fix**：卡片视图删除走同一个 `deleteTarget` state：`onDelete={(sub) => setDeleteTarget(sub)}`。ConfirmDialog 已在页面底部渲染。
- **Suggested command**：`harden`

### [P1] EntityManagerCard 删除无确认
- **What**：`EntityManagerCard` 点 trash 图标直接调 `onDelete(id)` → API delete，无 ConfirmDialog 无 undo。
- **Why it matters**：分类和支付方式是结构元数据。误删（即使 API 阻止 in-use 实体）侵蚀信任。产品已有 `ConfirmDialog` 组件 —— 应一致用于所有破坏性动作。
- **Fix**：给 `EntityManagerCard` 加 `deleteTarget` state + 渲染 `ConfirmDialog`，镜像 `SubscriptionsPage` 模式。
- **Suggested command**：`harden`

### [P2] Statistics "月度花费趋势"展示前向投影而非历史趋势
- **What**：`computeMonthlyProjection` 生成 12 个月前向投影，但标题叫"月度花费趋势"/"Monthly Spending Trend" —— 暗示历史数据。Dashboard 已移除假趋势换成诚实单数字，但 Statistics 没收到同样的诚实处理。
- **Why it matters**：用户看"趋势"图期望看到"发生了什么"，不是"预测什么"。前向投影当趋势展示是误导，违反 PRODUCT.md 原则 2"数字要能被信任"。
- **Fix**：要么改名为"未来 12 月预计支出"/"Next 12 Months Projection"，要么用真实历史数据替换。至少改标题 + 加副标题说明是投影。
- **Suggested command**：`clarify`

### [P2] pending 蓝用于正向"all clear"状态 — 颜色语义混用
- **What**："本月暂无到期"all-clear 卡用 `ring-pending/15` + `text-pending` ShieldCheck。`--pending` token 定义为"需关注/品牌焦点"语义 —— 即需要关注的事。all-clear 状态相反：不需要关注。
- **Why it matters**：DESIGN.md Color-as-Signal Rule"色彩出现时必须承载语义"。用"需关注"色表示"无需关注"反转了语义。如果 pending 蓝既能表示"紧急"又能表示"安全"，它失去精度。
- **Fix**：all-clear ShieldCheck 用中性色（`text-muted-foreground` 或未来加 `--success` token）。移除 `ring-pending/15` 或换中性 ring。
- **Suggested command**：`quieter`

### [P3] Due Soon 项相对时间标签重复（文字 + 徽章）
- **What**：Dashboard Due Soon 区域每项把 `formatDueLabel` 同时显示为名字下 `<p>` 和 Badge 文字。同一字符串"3天后"在一行出现两次。
- **Why it matters**：冗余信息增加视觉噪音不增加价值。徽章已通过 `pending` variant 传达紧迫，文字重复是杂乱不是强化。
- **Fix**：移除名字下的 `<p>` 文字标签（仅保留徽章），或移除徽章仅保留文字。徽章 + 相对时间是更强的配对。
- **Suggested command**：`distill`

## Minor Observations

1. `isDueSoon` 在 `SubscriptionsPage` 重复定义，未用 `lib/due.ts` 的 `isDueWithin`。逻辑略有差异。应用共享 helper。
2. Dashboard Due Soon 卡用 `ring-pending/20` —— DESIGN.md 列品牌锚点用于"badges, focus ring, auto-renew icon, acknowledge feedback"，未列 card ring。轻微越界。
3. Toaster 用 `shadow-sm` —— DESIGN.md 允许浮层用阴影，toast 是瞬时浮层所以允许，但值得注意它是唯一 `shadow-sm`。
4. `<html lang>` 未动态设置 —— i18n 切换语言但 `document.documentElement.lang` 未更新。屏幕阅读器会用错发音。
5. SubscriptionForm 无取消按钮 —— 依赖 dialog X 关闭。ConfirmDialog 有 cancel + confirm，表单也应有一致的 cancel。
6. Statistics 4 metric 卡 `text-2xl font-bold` 无 `tabular-nums` —— Dashboard 正确应用了。不一致。
7. `subscriptions.confirmDelete` i18n key 是死代码（被 `confirmDeleteTitle` + `confirmDeleteMessage` 替换）。
8. theme-toggle `&#10003;` + `aria-hidden` + `role="menuitemradio"` + `aria-checked` —— 正确。

## Questions to Consider

1. 如果 Dashboard 已证明一个诚实数字胜过误导图表，为什么 Statistics 还展示 12 月投影柱状图标题叫"趋势"？
2. 建了 ConfirmDialog 替换 `window.confirm` —— 但只在三个删除路径之一接线。有人实际点过卡片视图的 trash 图标吗？
3. "all clear"用和"due soon"一样的蓝色。色盲用户（或晚 11 点疲倦用户）看到蓝色该警觉还是安心？
4. SubscriptionForm 10+ 字段单滚动。产品价值主张是"减少操作的摩擦"，多少字段是首次添加真正必需的？
5. Statistics 有 4 metric + donut + top5 + 12 月柱状图。是在回答用户实际问题，还是"看起来专业"？PRODUCT.md 明确"不做图表展示型 dashboard"。
