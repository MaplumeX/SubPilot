## Overall Impression

骨架扎实，血肉失序。设计系统（graphite 灰阶 + ring 边缘 + Geist + 紧凑控件）是一套克制的、有主见的系统，但 UI 在两个关键处背叛了它：Statistics 的彩虹饼图和 Due Soon 的红色徽章。前者让产品看起来像 AI dashboard 模板，后者直接制造产品承诺要消除的焦虑。最大的机会：把 Dashboard 从"统计仪表盘"重构为"续费安全确认器"——让 Due Soon 成为第一视觉焦点，无 due 时显示明确的"本月安全"状态。这是产品存在的全部理由。

## What's Working

1. **Graphite 调色板 + ring 边缘层次系统执行到位。** `index.css` token 定义 + `card.tsx` 的 `ring-1 ring-foreground/10` 忠实实现 Flat-By-Default Rule。暗色模式是一等公民，token 完整反转。真正的设计系统思维，不是 AI 默认的 `shadow-lg rounded-2xl`。

2. **计费周期预设按钮是优秀的低摩擦模式。** `SubscriptionForm.tsx` 的 weekly/monthly/quarterly/yearly/custom 预设按钮组让 90% 用户一次点击完成周期设置，同时保留自定义入口。比常见的"数字 + 单位 dropdown"更贴合真实使用。

3. **Acknowledge 概念是产品的情感锚点。** 给用户一个具体动作回应"即将到期"，把被动焦虑转化为主动掌控 —— UX 概念方向正确，是产品差异化的种子。当前实现粗糙（只换徽章颜色），但概念值得打磨。

## Priority Issues

### [P0] Statistics 页彩虹饼图违反色彩系统
- **What**：`StatisticsPage.tsx:10-21` 硬编码 10 色数组用于 category distribution pie chart。
- **Why it matters**：UI 中最显眼的 AI-slop tell。违反 DESIGN.md 三条规则（Color-as-Signal、chart 全灰阶、"不加彩色分类标签"）和 PRODUCT.md"不做花花绿绿的理财 app"。用户从 Dashboard（全灰）切到 Statistics（彩虹），会瞬间觉得是两个产品，信任感断裂。
- **Fix**：替换为 CSS 变量 `[var(--chart-1)...var(--chart-5)]` 循环；考虑 donut chart + 图例列表替代 pie + 百分比标签。
- **Suggested command**：`colorize`

### [P0] Due Soon 使用红色徽章违反 Red-Only-for-Danger Rule
- **What**：`DashboardPage.tsx:87`、`SubscriptionsPage.tsx`、`SubscriptionCard.tsx:52` 用 `<Badge variant="destructive">` 标记即将到期。
- **Why it matters**：DESIGN.md 明确"destructive 红色只用于删除/不可逆危险动作，续费提醒不得使用红色"。PRODUCT.md 明确"不做焦虑营销型续费提醒"。红色把"即将续费"编码为"危险"，触发用户焦虑 —— 与产品存在核心理由直接矛盾。
- **Fix**：改为 `variant="secondary"` 或新建 `variant="pending"`（`brand-accent-pending` 色），或用时间文字"3 天后"替代徽章，完全靠位置 + 时间标注传达紧迫感。
- **Suggested command**：`quieter`

### [P1] Dashboard 信息层级违反"续费提醒优先"原则
- **What**：`DashboardPage.tsx` 渲染顺序 ① 3-stat grid → ② Due Soon → ③ 趋势图。PRODUCT.md 原则 1 要求 Due Soon 是第一视觉焦点，高于总额、高于趋势图。
- **Why it matters**：用户打开第一秒应看到"接下来几天有什么要扣款"，但第一眼是月度总额 —— 一个不回答"我安全吗"的静态数字。Due Soon 被推到第二位，趋势图（还是假数据）占第三位大量视觉空间。
- **Fix**：调整顺序为 ① Due Soon（或"本月安全"状态摘要）→ ② 月度总额 → ③ 趋势图（修复假数据后）。无 Due Soon 时显示明确的"本月无即将到期续费"肯定状态。
- **Suggested command**：`layout`

### [P1] Dashboard 月度趋势图使用假数据
- **What**：`DashboardPage.tsx:120-127` `generateChartData` 把 `stats.total_monthly` 复制 12 次，生成平线。
- **Why it matters**：这不是趋势，是误导。用户看到平线会以为"每月花销不变"，实际是当前月总额的 12 次重复。违反 PRODUCT.md 原则 2"数字要能被信任"。展示假趋势的图表比没有图表更糟。
- **Fix**：后端提供真实月度历史数据，或移除趋势图用"下月预计支出"单数字替代。不要展示无法支撑的数据可视化。
- **Suggested command**：`distill`

### [P1] muted-foreground 对比度不满足 AA（系统性）
- **What**：`index.css:34` `--muted-foreground: oklch(0.556 0 0)` = #737373 (Graphite 500)，对 Paper (#fff) 仅 4.0:1。广泛用于 `text-sm`/`text-xs` 次要文字、placeholder、loading、description、空状态 —— 全部 ≤14px 非粗体场景。涉及 input.tsx、DashboardPage、SubscriptionsPage、StatisticsPage、SettingsPage、card.tsx、AppLayout.tsx。
- **Why it matters**：DESIGN.md 自己已标注此问题（Muted-Foreground Contrast Rule）但代码未修复。PRODUCT.md 承诺 WCAG AA。系统性无障碍违规，影响所有次要文字可读性。
- **Fix**：将 `--muted-foreground` 改为 `oklch(0.371 0 0)` (Graphite 700, #404040, 9.0:1)。若需更浅装饰文字，新增 `--subtle-foreground` 专用于 ≥18px 场景。
- **Suggested command**：`harden`

## Persona Red Flags

### Alex（Power User）

主流程：打开 app → 看即将到期 → 确认安全。

1. 打开 Dashboard 第一眼是 3 个统计数字，Due Soon 在第二屏。**核心信息不在顶部。**
2. Due Soon 区域只有"Due Soon"标签，无"3 天后"时间标注。**缺乏可操作时间信息。**
3. 导航是 `<button>` 非 `<Link>`，cmd+click 新标签打开不工作。**导航非语义化。**
4. Subscriptions 表格无批量操作，想批量处理 3 个停用订阅只能逐行删除。**无效率操作。**
5. 筛选只有 category + status，无"未来 30 天到期"日期范围筛选。**缺乏高级筛选。**
6. Statistics 彩虹饼图让 Alex 质疑工具专业性。**可视化不可信。**

### Sam（Accessibility）

1. `muted-foreground` #737373 对白底 4.0:1 不满足 AA 4.5:1，次要文字吃力。**系统性红旗。**
2. 导航 `<button>` 屏幕阅读器不播报为导航链接，无 `aria-current="page"`。**导航语义缺失。**
3. 无 skip link，键盘用户每次页面切换要 Tab 穿过整个 header。**红旗。**
4. Loading "Loading…" 无 `aria-live="polite"`。**红旗。**
5. theme-toggle dropdown 用视觉 ✓ 标记当前项，无 `aria-checked`。**红旗。**
6. `window.confirm()` 与页面风格完全断裂。**红旗。**
7. acked 状态仅靠徽章颜色（红→灰）区分，无文字差异。**部分红旗。**

### 项目专属：焦虑的 Lin（Anxious Subscription Owner）

*"我打开 SubPilot 就是为了确认本月没有漏掉的续费，然后安心关掉。"*

1. 看到 ¥XXX 月/年总额 + 活跃数量，"这些数字不能告诉我有没有漏掉的续费"。**核心焦虑未被回应。**
2. 向下看到红色徽章，心跳加速 —— 这恰恰是 PRODUCT.md 说不该制造的焦虑。**红色触发焦虑。**
3. Due Soon 只显示原始日期 "2026-07-07"，无"3 天后"相对时间。Lin 要自己算。**缺乏人性化时间。**
4. 无 Due Soon 时区域不渲染，Lin 不确定是"没有到期"还是"加载失败"。**缺少安全确认状态。**
5. 带着未完全消除的焦虑关掉浏览器。**"放心关掉"未实现。**

### 项目专属：手机临时查看的 Mei

*"我在地铁上用手机看一眼这个月的订阅情况。"*

1. 3-stat grid 手机上变 1 列竖排，Due Soon 被推到更下面，要滚动过 3 个统计卡。**移动端层级更糟。**
2. Header 4 导航 + logo + theme toggle + email + sign out 全挤在 `px-6 py-3`，375px 必然溢出。无 hamburger、无响应式收起。**移动端导航不可用。**
3. Subscriptions 默认 table view 9 列 + `overflow-x-auto`，手机要横向滚动才看到操作按钮。**移动端默认视图不当。**
4. SubscriptionForm dialog `max-w-lg max-h-[90vh] overflow-y-auto` 是手机上全屏高度超长滚动表单，无步骤分割。**表单移动端体验差。**

## Minor Observations

1. `AppLayout.tsx:60` 全局"新增订阅"不刷新 Subscriptions 页列表（`handleCreate` 不 reload），与 SubscriptionsPage 自己的"新增"按钮（调 `reload()`）行为不一致。
2. `SubscriptionsPage.tsx:97` 用 `window.confirm` —— SPA 中最低级确认交互，不可定制、与品牌气质不符。应换 in-app 确认 dialog 或 swipe-to-delete + undo toast。
3. `SubscriptionCard.tsx` footer 当 `canAcknowledge` 时 3 个 `flex-1` 按钮（Edit/Delete/Acknowledge）等宽排列，destructive Delete 与 Acknowledge 并排易误点。Delete 应推远或降级为 icon button。
4. `StatisticsPage.tsx:148` 饼图 label `${name} ${percent}%` 在多类别小扇区会重叠不可读。应考虑图例列表 + donut。
5. `DashboardPage.tsx:43` 标题用 `text-2xl font-bold` 固定值，而 DESIGN.md Display 规范是 `clamp(1.5rem, 3vw, 2rem)` + 700 + letter-spacing -0.01em。Typography token 未被消费。
6. `AppLayout.tsx` 导航无 `aria-current="page"`，当前页仅靠视觉区分。
7. `theme-toggle.tsx` 菜单项标签硬编码 "Light"/"Dark"/"System"，其余 UI 全 i18n。
8. 无 `prefers-reduced-motion` 处理，PRODUCT.md 承诺"尊重 prefers-reduced-motion"。
9. `StatisticsPage.tsx:219,296` recharts Tooltip `borderRadius: "8px"` 不在 DESIGN.md 圆角规范（detector 命中，TRUE positive）。应改 10px 或 5px。

## Questions to Consider

1. **如果 Due Soon 区域是用户打开 app 的唯一理由，为什么它不是 Dashboard 的全部？** 想象极端版本：打开 app 第一屏只有"本月安全"或"3 天后 Netflix ¥58 将自动续费 — [我知道了]"。统计和趋势退到二级页面。是否更忠实于产品存在的理由？

2. **"Acknowledge" 是产品最独特的交互，但当前实现只把红色徽章换灰色 —— 如果这个动作值得存在，它是否值得一个有仪式感的反馈？** 200ms 的微动画 + 一行"好的，已记下，下次提醒 X 月 X 日"就能把焦虑转化为掌控感，当前实现浪费了这个情感机会。

3. **Statistics 的彩虹饼图和假趋势图 —— 是在回答用户的问题，还是在回答"一个 dashboard 应该有什么图表"？** PRODUCT.md 说"图表服务于问题，不服务于观感"。如果问题是"钱都花在哪了"，灰阶 donut + 图例就够了。
