## Overall Impression

SubPilot 的前端是一个克制、精准、有明确品牌主张的工具界面。它最大的成就是 **把"续费焦虑"转化成了平稳的信息分层** —— Due Soon 卡片用 pending 蓝 + 位置优先传达紧迫感，而非红色轰炸，完全兑现了 PRODUCT.md 的 "平稳的紧迫感" 承诺。设计系统的执行度很高：Committed 品牌蓝、ring-based elevation、Geist 单字体、紧凑控件 —— 这些决策在所有 7 个页面中保持一致。

最大的机会在 **用户控制的深度和首次使用的引导**：没有 undo、没有键盘快捷键、没有 onboarding、空状态只说"无数据"不教用户怎么做。这些不是视觉问题，是"工具是否让人愿意长期打开它"的产品深度问题。

## What's Working

1. **Due Soon 卡片的"平稳紧迫感"执行** — DashboardPage 顶部用 `ring-2 ring-pending/30 bg-pending/[0.03]` 的 Due Soon 卡片作为第一视觉焦点，配合 `formatDueLabel` 的相对时间（"3天后"），完全靠位置 + 时间标注传达紧迫，不用红色。acknowledged 状态用 success badge（绿）而非 pending，语义清晰。这是 PRODUCT.md 核心原则的最佳实现。

2. **Committed 品牌蓝的一致性** — 从 `--primary`（主按钮、logo 底、avatar）到 `--pending`（Due Soon badge、auto_renew 图标）到 `--sidebar-primary` 到 `--chart-1`（主数据线），hue 264 贯穿全栈。中性色全部微染（chroma 0.003-0.015），消除了纯灰的"死气"。暗色模式作为一等公民，不是简单反转。这是一套有纪律的调色板。

3. **日历的分层与本地化** — CalendarPage 的 DayCell 用 color+weight 分层（out-of-month `text-muted-foreground/35`、past `text-muted-foreground`、today `bg-primary` 实心圆），`getFirstDayOfWeek` 根据 locale 自动调整周首日，weekday 标签用 `Intl.DateTimeFormat` 本地化。事件 marker 用 `isDueSoon` 区分 due-soon（`bg-pending/15 ring-1`）和 far-future（`bg-pending/10`），把"续费优先"原则延伸到日历视图。

## Priority Issues

### [P1] 无 undo / 不可撤销的 acknowledge

**What**: `handleAcknowledge` 在 DashboardPage 和 SubscriptionsPage 中调用后立即从 due_soon 列表移除并显示成功 toast，但无 undo 路径。用户误点 "已确认" 后，该订阅从提醒中消失，直到下一个计费周期。

**Why it matters**: 这是核心流程的"误操作 → 数据丢失感"。PRODUCT.md 的"减少操作摩擦"原则意味着操作应该低风险，但当前 acknowledge 是单向不可逆的，与"冷静可靠"的承诺矛盾 —— 一个不慌不忙的助理应该允许你说"等等，我点错了"。

**Fix**: toast 上加 "撤销" 按钮，4 秒内点击恢复 acknowledged 状态（调一个 un-acknowledge API 或本地 state 回滚）。参考 Linear / Gmail 的 undo toast 模式。

**Suggested command**: `/impeccable harden`

### [P1] 统计页 loading 态与全局不一致

**What**: StatisticsPage loading 显示一行 muted 文字 `{t("statistics.loading")}`，而 DashboardPage / SubscriptionsPage / CalendarPage 都用 skeleton（`animate-pulse` 占位块）。Statistics 的空数据态也只是一行 `{t("statistics.noData")}` + `{t("statistics.addFirst")}`，无引导动作。

**Why it matters**: 同一产品内 loading/empty 状态的视觉词汇分裂，破坏"一致的工具"感。统计页是数据最密集的页面，用户对它的加载期望最高；一行文字让页面感觉"塌了"而非"在加载"。

**Fix**: 统计页 loading 改为 chart 区域的 skeleton（280px 高的 pulse 块 + 下方列表 skeleton）。empty 态加 "添加第一个订阅" 按钮（链接到 /subscriptions 或打开 form），参考 SubscriptionsPage 的 empty state。

**Suggested command**: `/impeccable polish`

### [P2] auto_renew 仅图标，无可见 label

**What**: SubscriptionsPage 表格和 SubscriptionCard 中 `auto_renew` 用 `<RefreshCw>` 图标 + `title` tooltip，无可见文字 label。颜色区分（`text-pending` vs `text-muted-foreground/80`）是次要编码。

**Why it matters**: 违反 PRODUCT.md Accessibility 原则"色彩不作为唯一信息编码"。图标 + title 对鼠标用户可用，但触摸设备无 hover，屏幕阅读器只读 "刷新图标"。对"自动续费是否开启"这种影响用户钱的信息，应可见可读。

**Fix**: 表格列头改为 "自动续费"，单元格内用 `<Switch>` disabled 预览态或 `Yes/No` 文字 + 图标。卡片视图同理。不要仅靠图标颜色。

**Suggested command**: `/impeccable clarify`

### [P2] 表格排序无键盘可访问性

**What**: `SortableHeader` 用 `onClick` 排序，`<TableHead>` 非 `<button>`，无 `tabIndex`、无 `onKeyDown`。`aria-sort` 正确设置了，但键盘用户无法聚焦到表头触发排序。

**Why it matters**: Accessibility 原则要求"键盘可完成所有主要操作"。排序是数据视图的核心功能，仅鼠标可用违反 WCAG 2.1.1。

**Fix**: `SortableHeader` 内部用 `<button>` 包裹 label + arrow，或给 `<TableHead>` 加 `tabIndex={0}` + `onKeyDown` 处理 Enter/Space。

**Suggested command**: `/impeccable audit`

### [P2] 空状态不教，仅说"无数据"

**What**: CalendarPage "无订阅" 空状态有 "添加第一个" 按钮（好），但 SubscriptionsPage 的空状态虽有按钮但文案是 `noSubscriptions` + `noSubscriptionsHint`（泛化）。StatisticsPage 空状态无任何引导动作。Dashboard 的 All-Clear 空状态做得好（ShieldCheck 图标 + 说明）。

**Why it matters**: PRODUCT.md "减少操作摩擦"要求首次使用低摩擦。空状态是首次用户接触的第一屏，"无数据"不教用户怎么开始，等于把用户关在门外。

**Fix**: 所有空状态统一模式：图标 + 一句说明 + 一个明确的下一步动作（"添加订阅"按钮或链接）。Statistics 空状态加 "去添加订阅" CTA。

**Suggested command**: `/impeccable onboard`

## Persona Red Flags

### Alex (Power User) — 检查即将续费 + 批量管理

- **无键盘快捷键**: 全程无快捷键。Alex 想用 `N` 新增订阅、`/` 搜索、`J/K` 导航列表 —— 都没有。每个操作都要鼠标点击。
- **无批量操作**: SubscriptionsPage 表格无法多选批量删除/编辑。Alex 有 20+ 订阅时，逐条操作很慢。
- **acknowledge 无 undo**: Alex 快速操作时误点 "已确认"，无法撤销，会失去对工具的信任。
- **表格行操作拥挤**: 每行 3-4 个按钮（编辑、确认、删除），无 overflow menu，窄屏会挤压。

### Sam (Accessibility-Dependent) — 键盘 + 屏幕阅读器

- **排序表头不可键盘聚焦**: `SortableHeader` 的 `<TableHead>` 非 button，无 tabIndex，Sam 无法用键盘排序。
- **auto_renew 仅图标**: 屏幕阅读器读 "RefreshCw 图标"，无法传达"自动续费开启/关闭"语义。需要 `aria-label` 或可见文字。
- **Due Soon 列表项语义**: `<li>` 内有多个交互元素（按钮、badge），但无 `role="listitem"` 的明确语义分组，屏幕阅读器导航可能混乱。
- **theme-toggle dropdown**: `DropdownMenuTrigger` 有 `aria-label`（好），但 `DropdownMenuItem` 用 `role="menuitemradio"` + `aria-checked`，base-ui 实现需验证是否正确暴露 checked 状态。

### Jordan (First-Timer) — 首次打开，不知道怎么开始

- **无 onboarding**: 首次登录直接到 Dashboard，无引导。Jordan 看到 "All Clear" 会困惑 —— "然后呢？我该添加订阅吗？"
- **空状态不教**: Statistics 空状态只说"无数据"，Jordan 不知道怎么解决。
- **SubscriptionForm 字段多**: 一次展示 10+ 字段（logo、name、price、currency、cycle、status、category、payment_method、start_date、notes、auto_renew、reminder），无分步或折叠，Jordan 会感到"这太复杂了"。
- **payment_method 必填但隐藏**: 表单提交后才报错 "请选择支付方式"，Jordan 可能不知道什么是"支付方式"（是信用卡？还是支付宝？）。

## Minor Observations

- `button.tsx` sm 变体 `text-[0.8rem]` 和 CalendarPage `text-[10px]` 脱离 type ramp —— 如果是刻意的紧凑尺寸，应在 DESIGN.md 登记 `caption` / `micro` 层级。
- Toaster 用 `animate-in fade-in-0 slide-in-from-bottom-2` —— 检查是否有 `prefers-reduced-motion` fallback（index.css 全局 media query 存在，应该覆盖）。
- SubscriptionForm 的 logo 搜索结果网格用 `<button>` 包 `<img alt="">`（空 alt）—— 应加 `aria-label={candidate.domain}` 或类似，让屏幕阅读器能区分。
- Dashboard HeroNumber 的 count-up 动画有 reduced-motion fallback（`reduce.current` 直接 setValue），好。
- AppLayout 的 nav 在窄屏会 `flex-wrap`，但未测试实际移动端可用性 —— `overflow-x-auto` 在 header 内可能产生横向滚动。
- SettingsPage 通知设置卡片 `max-w-lg`，其他卡片 `max-w-md` —— 宽度不一致，视觉节奏略乱。
- ConfirmDialog 的 `onConfirm` 是 fire-and-forget（`void onConfirm()`），如果 confirm 是 async 且失败，无错误反馈。

## Questions to Consider

1. **acknowledge 是否应该是"软"状态？** 当前它是从 due_soon 列表永久移除直到下个周期。如果它是"我已知悉，别再提醒我这次"的轻确认，撤销路径是否更符合"冷静可靠"？
2. **SubscriptionForm 能否分步？** 10+ 字段一次展示对首次用户是墙。能否默认折叠 reminder/logo/notes，只留核心 5 字段，"更多选项"展开？
3. **键盘快捷键是否值得投入？** Alex persona 的所有 red flag 都指向效率。一个 `N` 新增、`/` 搜索的 command palette 是否能让 SubPilot 从"好用"变"爱用"？
